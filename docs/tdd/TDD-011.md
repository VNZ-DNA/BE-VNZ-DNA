## Context & Goals

### Problem

Admin cần kéo thả các thành viên đang được đăng để kiểm soát thứ tự hiển thị trên website. Thành viên chưa đăng không được tham gia danh sách sắp xếp và không có DisplayOrder.

### Goals

- Hiển thị tên, vị trí, cấp bậc, EmploymentStatus, IsPublished và DisplayOrder.
- Chỉ thành viên IsPublished=true được kéo thả.
- Lưu thứ tự mới nguyên tử.
- Từ chối payload sắp xếp chứa thành viên chưa đăng.
- Website public đọc theo DisplayOrder tăng dần.

### Non-goals

- Không sắp xếp thành viên chưa đăng; nghiệp vụ Đăng/Gỡ đăng thuộc STORY-035.
- Không tạo hoặc chỉnh sửa hồ sơ thành viên; tạo thuộc STORY-012.
- Không gọi external API.

  API --> Svc[Member Ordering Service]
  Svc --> Repo[User Repository/AppDbContext]
  Repo --> DB[(PostgreSQL)]

~~~

Trong repository hiện tại, thành viên được biểu diễn bằng User. IsPublished là trạng thái hiển thị và DisplayOrder là thứ tự hiện tại. Service chỉ lấy User đủ điều kiện, kiểm tra toàn bộ payload rồi cập nhật DisplayOrder trong một transaction. Public website chỉ đọc User có IsPublished=true theo DisplayOrder.

## Internal API

### Endpoints

- GET /api/v1/admin/members — lấy danh sách thành viên cho Admin.
- PUT /api/v1/admin/members/display-order — lưu thứ tự thành viên đang đăng.
- GET response item gồm id, fullName, position, jobLevel, employmentStatus, isPublished và displayOrder.
- GET hiển thị Published theo DisplayOrder tăng dần; Unpublished có displayOrder null và không draggable.
- PUT body gồm orderedMemberIds: array Guid, required, không rỗng, không duplicate.
- orderedMemberIds phải chứa đúng toàn bộ User đang IsPublished=true tại thời điểm kiểm tra; không được chứa User IsPublished=false.
- Server tự gán DisplayOrder từ 1 đến N theo thứ tự array.
- Update và commit trong một transaction; không cập nhật nếu validation thất bại.
- Concurrent reorder phải re-read tập Published trong transaction; nếu tập đã thay đổi thì trả conflict và giữ thứ tự hiện tại.
- Public query chỉ trả IsPublished=true và sort DisplayOrder tăng dần.

### Examples

#### GET danh sách

~~~http
GET /api/v1/admin/members
~~~

HTTP 200 trả danh sách gồm cả Published và Unpublished; Published có DisplayOrder, Unpublished có null.

#### PUT sắp xếp thành công

~~~json
{
  "orderedMemberIds": [
    "11111111-1111-1111-1111-111111111111",
    "22222222-2222-2222-2222-222222222222"
  ]
}
~~~

HTTP 200; hai User được gán DisplayOrder lần lượt 1 và 2; website public hiển thị cùng thứ tự.

#### Kéo thành viên chưa đăng

HTTP 400 MEMBER_ORDER_INVALID; không đổi DisplayOrder cũ.

#### Payload thiếu hoặc duplicate

HTTP 400 MEMBER_ORDER_INVALID; không ghi database.

#### Authentication/authorization failure

HTTP 401 khi chưa xác thực; HTTP 403 khi không có quyền Admin. Không ghi database.

#### Persistence/concurrency failure

HTTP 409 MEMBER_ORDER_CONFLICT khi tập Published thay đổi trong lúc reorder; HTTP 500 MEMBER_ORDER_UPDATE_FAILED khi transaction/database failure. Thứ tự cũ được giữ nguyên.

### Error Codes

- AUTHENTICATION_REQUIRED (401): thiếu hoặc sai phiên đăng nhập.
- FORBIDDEN (403): người dùng không có quyền Admin.
- MEMBER_ORDER_INVALID (400): id sai, duplicate, thiếu published member hoặc chứa unpublished member.
- MEMBER_ORDER_CONFLICT (409): dữ liệu Published thay đổi đồng thời.
- MEMBER_ORDER_UPDATE_FAILED (500): lỗi persistence/transaction; rollback toàn bộ.
